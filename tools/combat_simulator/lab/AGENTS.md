# Combat lab

Apply the root project instructions and Godot conventions to any Godot bridge code.

**Model boundary:** this lab retains the pre-2.0 combat model, its bundled schema-2 snapshot and `../legacy_combat_rules_v1.json`. Live Godot now uses schema 3 and is unsupported by this engine. Python import and the Godot bridge must reject it before replacing any snapshot. Keep the legacy identity visible in the interface and results; no legacy-versus-live attribute parity claim is valid after this migration.

- This is an offline Python/NumPy time-to-kill tool with a Tkinter desktop interface. Do not open the interface or other desktop applications without explicit permission. Importing modules, headless Godot exports, and non-UI tests are appropriate verification.
- Keep experiment settings and actor/ability definitions serializable as JSON. Loading, editing, and running experiments must not write gameplay resources or `combat/combat_rules.json`.
- Use the existing simulator's shared mathematical helpers. Read frozen defaults from the legacy rules and bundled Godot catalogue; avoid separate manually maintained attribute IDs or invented itemization prices. A future 2.0 import requires an explicit engine migration and new parity checks.
- `model.py` owns experiment validation, actor attribute evaluation, saved-game imports, and matrix expansion. `engine.py` owns independent repeated encounters and result aggregation. `app.py` coordinates the interface and background work. `widgets.py` owns curve and results presentation.
- The encounter measures repeated use of one selected ability against a target that does not attack back. It assumes authored deliveries physically connect. Dodge, Block, accuracy, criticals, resource costs/regeneration, cooldown/action timing, defenses, automatic ailments, Absorption recovery, and authored damage-over-time effects still apply. Passive Health regeneration and healing effects are retired; consumable restoration is an explicit external policy. Do not describe these trials as AI duels or skill/movement simulations.
- Periodic damage snapshots its ordinary noncritical magnitude. Generic Refresh preserves magnitude and phase; Replace takes a new snapshot; ordinary Stack has a finite limit. Automatic Burn/Bleed use strongest global-family policy and automatic Poison uses uncapped independent stacks. Direct critical Hits guarantee eligible ailments; ticks never trigger more ailments. Final due ticks occur before expiration. Failed delivery applies no dependent effects, and ticks never reroll delivery accuracy.
- Report timeouts and resource-depleted trials explicitly. Kill-time percentiles are conditional on kills; do not replace an unobserved kill time with the horizon or silently omit failures from the kill rate.
- Background work receives an immutable experiment snapshot. Tk widgets are accessed only on the main thread; use queue messages for progress, cancellation, results, and errors. Chunk trials to bound memory and permit cancellation.
- Keep tests focused on independent numerical expectations, complete delivery behavior, resource/tick clocks, matrix expansion, input validation, reproducibility, and game parity. Do not test GUI colors or font sizes.
- Document any unsupported effect kinds or execution behavior at import rather than silently presenting approximations as exact game behavior.

- Frozen rules use unified Hit Rating, Magic Power, separate DoT Damage, Critical Damage bonus, Cold/Void/Necrotic schools, and Absorption. Reject stale retired-stat experiments and schema-3 experiments rather than silently interpreting their values as equivalent. Use the frozen source revision in provenance.
- Resolve retains ID24 and its eligible-control duration reduction. Stamina/Mana Cost Efficiency IDs28/29 are retired; source costs are authored amounts. Update the exported active catalogue and rule keys together without editing historical experiment snapshots.
- Optional weapon min/max damage and base attacks/second are legacy simulation inputs. They do not represent Godot's new WeaponDefinition or Physical Power scaling. The separate leveling study models two-sided fixed-contact pressure; do not attribute its scope to this one-way lab.
- Current first-pass formula analysis uses no Health restoration and reports player-to-enemy and enemy-to-player TTK independently. Consumables are not implemented; do not add hypothetical potion, charge, cooldown or refill assumptions to that baseline. Existing Absorption recovery and Stamina/Mana regeneration remain active.
